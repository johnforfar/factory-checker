# Mini App Review Dashboard - Architecture & Processes

This directory contains a comprehensive dashboard and automation system for assessing the quality of Mini Apps generated by the Mini App Factory.

## Purpose

The system tracks, discovers, and visually assesses apps to distinguish between:
- **High-quality "Vibe Coded" apps**: Customized apps with unique titles, descriptions, and functionality
- **"Default Template" apps**: Apps that haven't been customized (title = "Mini App Factory App")

## Architecture Overview

The system operates on a **"Source of Truth" model** using a local state file (`apps-state.json`) and Git submodules for change detection.

### Data Sources

- **`apps-state.json`**: JSON database tracking app metadata:
  - `title`: App title (from `metadata.ts` or GitHub)
  - `status`: "Active", "Default", or "Pending"
  - `last_updated`: GitHub repository last update timestamp (ISO format)
  - `last_checked`: When we last checked the app for default status
  - `last_assessed_hash`: Git commit hash of last assessment
  - `commits`: Number of commits in the repository
  - `description`: One-liner description from GitHub or metadata
  - `builder`: Wallet address of the app creator (if available)
  - `repo_url`: GitHub repository URL
  - `landing_url`: Live marketplace URL

- **`apps.csv`**: CSV export/report (974 apps currently tracked)

- **`../apps/`**: Directory containing Git submodules for each tracked app repository

- **`public/apps/[app-name]/`**: Directory containing:
  - `logo.png`: App icon
  - `screenshot-1.png`, `screenshot-2.png`, etc.: Visual assessments

### Core Scripts

#### 1. Discovery & Initial Setup

- **`discover_repos.py`**: 
  - Scrapes GitHub organization page (`https://github.com/miniapp-factory?tab=repositories`)
  - Parses HTML to extract repository names
  - Updates `apps.csv` with new apps
  - Handles pagination (30 repos per page)

- **`sync_csv_to_state.py`**:
  - Syncs `apps.csv` entries to `apps-state.json`
  - Initializes new apps with "Pending" status

#### 2. Git Submodule Management

- **`manage_apps.py`**:
  - Reads app list from `apps.csv`
  - Adds/updates Git submodules in `../apps/` directory
  - Uses `git submodule update --init --remote --jobs 8` for parallel updates
  - Compares current commit hash with `last_assessed_hash` in state
  - Updates `apps-state.json` with `last_seen_hash`, `last_updated_ts`, and `needs_assessment` flag if changes detected

#### 3. Default App Detection

- **`fast_flag_defaults.py`**:
  - Checks `metadata.ts` file via GitHub raw content API
  - Looks for `title = "Mini App Factory App"` or default description
  - Updates `apps-state.json` with status ("Default" or "Active")
  - Sets `last_checked` timestamp
  - Uses random delays and User-Agent rotation to respect GitHub rate limits
  - Runs in background with 4 concurrent workers

- **`flag_defaults.py`** (Alternative):
  - Checks local submodule files (`apps/[app]/mini-app/lib/metadata.ts`)
  - Faster but requires submodules to be cloned first

#### 4. Data Enrichment

- **`update_dates_from_list.py`**:
  - Scrapes GitHub repositories list page
  - Extracts "Last Updated" timestamps from `<relative-time>` tags
  - Updates `apps-state.json` with ISO-formatted dates
  - Processes all 972 apps efficiently

- **`fetch_details.py`**:
  - Scrapes individual GitHub repository pages
  - Extracts commit count from page HTML
  - Extracts repository description
  - Updates `apps-state.json` with `commits` and `description` fields
  - Runs in background with 5 concurrent workers

- **`fetch_icons.py`**:
  - Downloads `logo.png` from GitHub raw content
  - Saves to `public/apps/[app-name]/logo.png`
  - Skips apps that already have icons
  - Runs in background with 5 concurrent workers

#### 5. Visual Assessment

- **`run_assessment.py`**:
  - Reads `apps-state.json`
  - Copies `logo.png` from submodules to `public/apps/[app-name]/`
  - Identifies apps needing screenshots

- **Screenshot Process** (Manual via Cursor Browser):
  - Navigate to `https://[app-name].miniapp-factory.marketplace.openxai.network`
  - Take screenshot using `browser_take_screenshot`
  - Save to `public/apps/[app-name]/screenshot-1.png`
  - Move from temp location to final destination

#### 6. State Management

- **`patch_completed_apps.py`**:
  - Manually marks apps as "Completed" (has icon, screenshot, status, dates)
  - Sets `last_checked` timestamp for apps with screenshots

- **`repair_state.py`**:
  - Recovers corrupted `apps-state.json` files
  - Uses regex to extract valid data from corrupted JSON
  - Rebuilds state from `apps.csv` and recovered data

### Dashboard (Next.js)

#### Server Component (`app/page.tsx`)

- Reads `apps-state.json` and `public/apps/` directory
- Formats dates for display
- Passes data to client component
- Provides `rawDate` and `lastCheckedRaw` for relative time calculations

#### Client Component (`app/dashboard-client.tsx`)

**Features:**
- **Real-time Stats**: Total, Active, Default, Completed, Pending counts
- **Dashboard Data Timestamp**: Shows "Last updated [relative time]" based on most recent app update
- **Search**: Filter by name, title, or description
- **Status Filter**: All, Active, Default, Pending
- **Completed Filter**: Show only fully processed apps (has status, icon, screenshots, checked date, GitHub date)
- **Sorting**: Click column headers to sort (Name, Status, Github Update, Last Checked)
- **Relative Time**: Displays "2 hours 13 minutes ago" format for dates
  - **Timezone-Safe**: All date calculations run client-side using browser's local time
  - **Vercel-Compatible**: Works identically on localhost and production (no server timezone issues)
  - Uses ISO strings from server, parsed by client's Date constructor
- **Screenshot Modal**: Click screenshots to view full-screen
- **Auto-refresh**: Refreshes data every 10 seconds

**Table Columns:**
1. **#**: Rank (1, 2, 3...)
2. **App**: Icon, title (linked), name, description
3. **Builder**: Wallet address (shortened format: `0x1234...5678`)
4. **Screenshots**: Thumbnail grid (up to 3 visible)
5. **Status**: Badge (Active/Default/Pending)
6. **Github**: 
   - Last Update: [relative time]
   - Commits: [count]
   - Commit hash (if available)
7. **Last Checked**: [relative time]

## Workflows

### Initial Setup

1. **Discover All Apps**:
   ```bash
   python3 discover_repos.py
   ```
   This scrapes GitHub and populates `apps.csv` with all 972+ apps.

2. **Sync to State**:
   ```bash
   python3 sync_csv_to_state.py
   ```
   Creates `apps-state.json` with all apps marked "Pending".

3. **Update Dates**:
   ```bash
   python3 update_dates_from_list.py
   ```
   Populates GitHub last updated timestamps.

### Ongoing Operations

1. **Background Processes** (Run in parallel):
   ```bash
   python3 fast_flag_defaults.py &      # Check for default apps
   python3 fetch_icons.py &               # Download icons
   python3 fetch_details.py &             # Get commits & descriptions
   ```

2. **Visual Assessment**:
   ```bash
   python3 run_assessment.py              # Copy icons
   # Then manually take screenshots using Cursor Browser
   ```

3. **Monitor Changes**:
   ```bash
   python3 manage_apps.py                 # Update submodules, detect changes
   ```

### Viewing Results

1. **Start Dashboard**:
   ```bash
   cd app-review
   npm run dev
   ```

2. **Access**: `http://localhost:3001`

3. **Features**:
   - Filter by status or "Completed Only"
   - Search by name/description
   - Sort by any column
   - View screenshots in modal
   - See real-time stats

## Data Flow

```
GitHub Repos → discover_repos.py → apps.csv
                                    ↓
                            sync_csv_to_state.py
                                    ↓
                            apps-state.json (Source of Truth)
                                    ↓
        ┌───────────────────────────┼───────────────────────────┐
        ↓                           ↓                           ↓
fast_flag_defaults.py    fetch_icons.py          fetch_details.py
        ↓                           ↓                           ↓
   (status)                    (icons)                  (commits, desc)
        └───────────────────────────┴───────────────────────────┘
                                    ↓
                            apps-state.json (Updated)
                                    ↓
                            Dashboard (Next.js)
                                    ↓
                            User Interface
```

## Key Files

- **`apps-state.json`**: The database (972+ apps)
- **`apps.csv`**: CSV export (974 apps)
- **`public/apps/[app-name]/`**: Assets (icons, screenshots)
- **`app/dashboard-client.tsx`**: UI logic, filtering, sorting
- **`app/page.tsx`**: Server-side data fetching

## Background Processes

The system runs several background scripts simultaneously:

1. **Default Checker**: Processes ~900 apps, checking metadata.ts files
2. **Icon Fetcher**: Downloads logos for all apps
3. **Details Fetcher**: Scrapes commit counts and descriptions

All scripts:
- Use random delays (0.5-3 seconds) to respect rate limits
- Rotate User-Agent strings
- Save progress periodically (every 10-50 apps)
- Handle errors gracefully

## Performance

- **Discovery**: ~30 seconds for 972 apps (33 pages)
- **Date Updates**: ~35 seconds for 972 apps
- **Default Checking**: ~30-60 minutes for 900 apps (with delays)
- **Icon Fetching**: ~15-30 minutes for 900 apps
- **Details Fetching**: ~2-4 hours for 900 apps (individual page scraping)
